# 教育与企业 SRC 工具部署及角色边界

## 适用范围

`EDUSRC渗透测试`、`企业SRC渗透测试`使用 `src-low-impact` 策略，服务端限制与角色提示词共同生效。其他角色保留原配置；空 `tools` 列表在普通角色中仍表示全部可用工具，不能用于这两个受限角色。

## 工具部署

Ubuntu 主机需要 Python 3（含 venv）、Git、curl、Go、apt-get、dpkg-deb，并可访问官方软件源。使用运行项目的普通用户执行：

```bash
bash tools/install-src-tools.sh
```

安装程序不使用 sudo。程序、依赖、缓存、日志和版本清单位于 `tools/runtime/`，该目录不进入 Git 或 Docker 构建上下文。需要为安装目录预留磁盘空间。下载或版本校验失败会停止安装，修复网络或系统依赖后可重试。

| MCP 工具 | 项目内依赖 | 用途 |
| --- | --- | --- |
| http-framework-test | Python venv、httpx 及可选传输依赖 | 单个 HTTP 请求验证 |
| nmap | Ubuntu 包解压目录及动态库 | 单主机少量端口 TCP 连通检查 |
| jwt-analyzer | 固定提交的 jwt_tool、Python 依赖 | 测试 JWT 离线结构检查 |
| api-schema-analyzer | Node、Spectral、固定内置规则集 | 本地 OpenAPI 静态分析 |
| waybackurls | 固定版本 Go 程序 | 当前域名的历史 URL 查询 |

Python venv 继承系统站点包以保留其他工具已有依赖，新安装包只写入项目目录。Node 下载校验官方 SHA-256；Nmap 使用已配置 Ubuntu 软件源的包元数据；Python 与 Spectral 记录解析后的依赖版本。维护时应再次执行依赖漏洞检查，安装成功不代表未来始终无漏洞。

JWT 安装包含两处受校验的兼容修正：生成 INI 时仅以 `=` 为分隔符，避免 Python 3.14 对注释中冒号的校验异常；正常解析完成后返回成功退出码，显式校验失败仍返回错误。安装器检查源码是否符合固定版本与预期补丁，保留有效配置、备份不完整的初始配置，并验证正常与无效测试令牌。

工具配置的裸命令名优先解析同一工具目录下的 `runtime/bin`，再查找系统 PATH；显式绝对路径仍按配置执行。安装后重新加载工具配置或重启服务，让工具可用性说明更新。Windows/macOS 的解析逻辑支持本机可执行文件，但此安装脚本仅用于 Ubuntu，不能直接安装 Linux 二进制到 Windows。

## 服务端限制

角色配置示例：

```yaml
tool_policy:
  profile: src-low-impact
  max_network_calls: 50
  min_interval_ms: 1000
  max_ports: 10
```

- 每次运行仅允许第一个网络工具调用选定的主机；网络工具调用默认最多 50 次、间隔至少 1 秒、串行执行。子代理共享限制。一个 Nmap 调用仍可能产生多个 TCP 包；调用数不是网络包数。
- HTTP 只允许 GET、HEAD、OPTIONS；每次一个请求，关闭重定向、调试和命令回显，超时 10 秒，返回正文限制为 8192 字节及 100 行。
- Nmap 必须提供最多 10 个明确端口；拒绝 CIDR、主机列表、端口范围、NSE、服务探测和附加参数，使用受限 TCP 连接检查选项。
- JWT 仅接受测试令牌参数；禁止在线目标、签名破解及额外攻击参数。修正令牌的位置参数与目标 URL 的 `-t` 参数映射。
- Spectral 只接收不超过 2 MiB 的本地 OpenAPI/Swagger 文档，仅允许文档内引用，禁止自定义规则和额外参数。
- Waybackurls 强制排除子域结果，不自动访问返回的 URL。查询本身会联系历史索引服务。
- 禁止 shell、任意 Python 脚本、包安装、批量任务和不在角色清单内的工具；本地执行权限不能覆盖角色限制。
- 普通对话、机器人、工作流和子代理使用同一策略机制；旧版角色编辑客户端省略策略字段时保留原策略。受限工具等待完成，单次工作进程最多运行一分钟，避免异步返回后释放串行执行位置。

额度属于一次运行的上下文，不是账号或项目的持久配额；新运行及跨请求的工作流恢复会创建新额度。平台操作员仍需控制任务创建频率。

## 提示词与授权边界

角色提示词禁止高危利用、大量批量扫描、真实个人信息读取及业务状态变更。教育角色特别保护师生及未成年人数据，企业角色要求遵守目标 SRC 平台规则。未知问题必须区分“疑似”“未验证”“环境受限”，不得包装成已确认漏洞。

服务端参数限制无法判断任意 GET 请求的业务语义，也不会从第一个 URL 推断授权；GET 接口仍可能改变状态。运行前须明确获授权的主机、端口、路径和测试身份，使用自建测试记录。响应异常后的停止、同一假设最多三次差分等要求由提示词约束，不能当作已经实现的网络防火墙或完整沙箱。

缺失命令由部署维护流程补装后重载。受限角色不会得到 Python 降级建议，也不能用子代理绕过范围。其余角色仅在自身工具权限允许且依赖存在时使用等价替代方案。

## 验证与回滚

无真实目标的回归命令：

```bash
go test ./tests/internal/rolepolicy ./tests/internal/config
go test ./internal/multiagent -run 'TestSRCMiddleware'
CSAI_SRC_TOOLS_DIR="$PWD/tools" go test ./tests/internal/rolepolicy -run TestInstalledSRCTools -v
```

最后一条使用临时回环 HTTP 服务、单个回环端口、无权限的测试 JWT 和临时 OpenAPI 文件；不会查询真实域名的历史记录。Waybackurls 验证安装入口，不证明第三方历史索引服务可用。

部署前备份应用二进制、角色 YAML、相关工具 YAML 和配置文件。先在独立源码目录构建测试，再替换应用与两个角色文件；不要覆盖数据库、凭据、其他工具配置或运行数据。回滚时停止本次启动的进程，恢复配套二进制与配置，按原启动方式恢复服务。`tools/runtime` 可先改名保留用于回退；恢复旧角色配置可能恢复较宽的工具权限，应由维护人员明确选择。
