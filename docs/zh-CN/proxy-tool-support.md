# 代理工具支持范围

在「设置 → 代理池 → 工具代理支持状态」查看接入能力。该清单不表示工具已经安装、启用，或账号具有调用权限。

| 状态 | 执行规则 |
| --- | --- |
| 已支持 | `http-framework-test` 注入固定会话代理，保留原有权限检查 |
| 内部操作 | 资产、漏洞、事实、任务和已登记的本地读取操作无需代理 |
| 待验证（已阻止） | 扫描工具尚未验证所有模式、内部并发和出站路径，启用代理池后不能执行 |
| 不支持（已阻止） | 任意脚本、外部 MCP 和未登记工具不能借通用执行入口绕过代理规则 |

代理池选择按账号保存。同一会话使用固定节点；不同会话可能选择不同节点。此功能不是整台服务器的全局固定出口，也不会代理模型 API。故障、冷却和节点移除不会触发自动轮换或直连；用户显式更改代理池会改变后续选择。

待验证工具不能通过修改界面或配置白名单直接启用。新增适配应先验证工具版本、限定模式、代理参数覆盖、重定向、DNS、子进程、内部限速及故障分类。应用层工具准入不等于操作系统网络隔离。

## 管理接口

`GET /api/test-proxy-pools` 需要登录并具有 `config:write` 权限。现有响应新增 `tool_capabilities`，例如：

```json
{
  "tool_capabilities": [
    {
      "name": "http-framework-test",
      "status": "supported",
      "reason": "Fixed session proxy; no automatic rotation or direct fallback"
    }
  ]
}
```

状态由服务端准入策略提供。未知状态按不支持展示；旧服务没有该字段时显示状态不可用，不推断已支持。此接口为有界能力清单，不接受分页或修改能力参数。正常返回 200，未登录 401，无权限 403，读取失败 500，代理服务不可用 503。

## 验证与部署

Linux 下执行 `go test ./tests/internal/testproxy ./internal/handler`，以及配置 Playwright 后运行 `node tests/browser/test-proxy.cjs`。浏览器测试覆盖四类状态、未知状态、旧服务兼容、输出转义与明暗主题。

代码按 dev → main PR 发布。更新服务与前端静态资源后刷新页面；回滚时同时恢复上一个部署版本的二进制及静态资源。本变更不修改数据库结构、代理偏好或节点数据。

## 运行入口核验

工具支持表同时显示代理支持和运行入口，两者独立：

- 已找到可执行入口：按照执行器相同规则检查项目托管工具目录及 PATH，不运行版本命令或发送网络请求。
- 入口缺失或不可执行：需要维护工具安装；托管入口存在但不可执行时，不回退到系统同名命令。
- 已停用／未配置：读取当前生效配置；修改并应用配置后刷新页面。
- 已注册内部工具：当前 MCP 注册表中存在该内部工具。
- 取决于会话／服务：由会话模式或外部服务提供，不能从本地可执行文件推断状态。
- 未核验：旧服务未提供字段，或返回未知状态。

响应中的 `runtime` 对应 `command_found`、`command_missing`、`disabled`、`not_configured`、`registered`、`session_dependent`。这不是完整依赖测试或账号授权检查；例如找到 Python 解释器仍可能缺少模块。页面刷新会重新核验入口；服务不返回本地安装路径或运行凭据。核验结果不改变代理准入规则。
