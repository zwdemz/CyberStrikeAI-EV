# 排错指南

本文按现象列出常见问题。优先查看服务日志、浏览器控制台和 `/api-docs` 中的接口响应。

## 无法访问页面

检查：

- 服务是否启动。
- 端口是否被占用。
- 配置中是否启用 HTTPS。
- 访问协议是否正确。

默认配置常见地址：

```text
https://127.0.0.1:8080/
```

如果使用自签证书，浏览器会提示不受信任，需要手动继续访问。

## 登录失败

检查：

- RBAC 用户密码是否正确（默认 `admin`；首次启动密码见控制台输出）。
- 是否修改密码后旧会话已失效，需重新登录。
- 浏览器 Cookie 是否异常，可尝试无痕窗口。
- 审计日志中是否有登录失败节流。

### 忘记 `admin` 密码

如果仍有其他具备 `rbac:write` 权限的管理员账号，优先在 **平台权限 → 用户管理** 中重置密码。

如果没有可用的管理员会话，可在服务器上紧急重置内置 `admin` 账号。在项目根目录执行：

```bash
./run.sh --reset-admin-password
```

按提示输入并确认新密码。脚本会隐藏输入并写入 bcrypt 哈希。如果服务正在运行，完成后重新启动服务，使原有登录会话失效。

如果无法使用 `run.sh`，也可以手动执行以下命令，按提示输入并确认新密码：

```bash
HASH=$(htpasswd -nBC 10 '' | cut -d: -f2 | tr -d '\n') && sqlite3 data/conversations.db "UPDATE rbac_users SET password_hash='$HASH', updated_at=CURRENT_TIMESTAMP WHERE id='admin' AND username='admin' AND is_builtin=1; SELECT changes();"
```

输出 `1` 表示修改成功。该命令需要 `sqlite3` 和 `htpasswd`；如果 `config.yaml` 中的 `database.path` 不是默认值，请替换 `data/conversations.db`。密码输入不会显示，也不会写入 Shell 历史。

## 模型无响应

检查：

- 当前对话选择的 AI 通道是否存在；为空时会使用 `ai.default_channel`。
- `ai.channels.<id>.base_url` 是否包含正确路径，如 `/v1`。
- `ai.channels.<id>.api_key` 是否有效。
- `ai.channels.<id>.model` 是否存在。
- 服务商是否支持当前通道的 `reasoning` 字段。

可在系统设置中使用模型测试。若网关报 400，先尝试：

```yaml
ai:
  channels:
    your-channel:
      reasoning:
        mode: off
```

## 流式输出中断

常见原因：

- 反向代理缓冲 SSE。
- 模型网关超时。
- 浏览器网络断开。
- 上下文过大。

Nginx 需要：

```nginx
proxy_buffering off;
proxy_http_version 1.1;
```

## 工具执行失败

检查：

- 工具命令是否已安装到 PATH。
- `tools/*.yaml` 参数 schema 是否正确。
- 是否被 HITL 拒绝。
- 是否超过 `agent.tool_timeout_minutes`。
- Shell 长时间无输出是否触发 `shell_no_output_timeout_seconds`。

工具配置可参考 `tools/README.md`。

## MCP 连不上

内置 MCP：

- 检查 `mcp.enabled`。
- 检查 `mcp.port`。
- 检查 `auth_header` 和 `auth_header_value`。

外部 MCP：

- stdio：检查命令路径、工作目录、环境变量。
- HTTP/SSE：检查 URL、认证、网络连通性。
- 查看 `/api/external-mcp/stats`。

## 知识库不可用

检查：

- `knowledge.enabled: true`。
- embedding 配置是否正确。
- 是否已经扫描并重建索引。
- `data/knowledge.db` 是否可写。
- 嵌入服务是否 429 或超时。

如果索引大量失败，降低：

```yaml
knowledge:
  indexing:
    batch_size: 5
    rate_limit_delay_ms: 600
```

## 机器人没有回复

检查：

- 对应平台 `robots.<platform>.enabled`。
- 平台回调 URL 是否指向 `/api/robot/...`。
- Token、secret、verify_token 是否一致。
- 服务器是否可被平台访问。
- 群聊是否需要 @ 机器人。

详细步骤见 [机器人使用说明](robot.md)。

## C2 监听器启动失败

检查：

- `c2.enabled`。
- 端口是否被占用。
- 防火墙或安全组。
- 是否需要管理员权限绑定低端口。

关闭 C2 后 `/api/c2/*` 返回 503 是预期行为。

## WebShell 命令乱码

处理：

- 确认目标系统编码。
- 尝试更短命令。
- 使用 base64 包装输出。
- Windows 目标检查代码页。

## 数据库锁或写入失败

检查：

- `data/` 是否可写。
- 是否多个实例共用同一个 SQLite 文件。
- 磁盘是否满。
- 是否异常复制了 WAL/SHM 文件。

生产环境不要让多个进程同时写同一份 SQLite 数据库。

并行 `create_asset` / `update_asset` 曾可能在去重查询后的读事务升级写锁时立即失败。现在主库事务先取得写锁，连接池上限为 8，锁等待最多 10 秒；若 SQLite 仍报告 BUSY，整批回滚后最多再重试两次。单条资产更新也使用有限重试。Agent 或 HTTP 请求取消后会停止等待；校验失败、权限不足和其他 SQL 错误不会重试。

若超过有界等待仍报锁冲突，Agent 会收到可重试提示，HTTP 资产接口返回 503。请检查其他写入进程、磁盘及长时间导入任务。此前失败的资产不会自动补录：按原授权范围核对资产库和来源结果，重新提交缺失目标；去重键可防止重复行。部署前备份程序与 SQLite 数据库，更新服务端并重启；无需迁移表结构或改配置，回滚时恢复旧程序即可。

## 前端页面异常

检查：

- 浏览器控制台错误。
- 静态资源是否加载成功。
- 修改前端后是否刷新缓存。
- i18n key 是否缺失。

接口异常时打开 `/api-docs` 对照请求体。

## 诊断顺序

遇到问题时不要直接改配置，先定位层级：

1. 进程：服务是否还在，日志是否有 panic。
2. 网络：端口、HTTPS、反向代理、浏览器控制台。
3. 认证：`/api/auth/validate` 是否 200。
4. 配置：`/api/config` 是否能读，应用后是否报错。
5. 模型：模型测试是否通过。
6. 工具：工具列表和单个 schema 是否正常。
7. 数据库：`data/` 是否可写，有无锁。
8. 业务模块：知识库、MCP、C2、WebShell 分别测最小动作。

先定位层级，再改参数。否则容易把一个代理问题误判成模型问题。

## 最小诊断命令

```bash
# 进程和端口
lsof -i :8080

# 本机 HTTPS 是否通
curl -k -I https://127.0.0.1:8080/

# 静态资源是否通
curl -k -I https://127.0.0.1:8080/static/logo.png

# 查看数据库文件
ls -lh data/
```

如果经过 Nginx，再分别测代理地址和回源地址，确认问题在哪一层。

## 常见误判

- “模型坏了”：实际是 HITL 挂起等待审批。
- “工具没加载”：实际是 tool_search 隐藏了大部分工具。
- “知识库没效果”：实际是索引没重建或 risk_type 过滤过窄。
- “C2 接口坏了”：实际是 `c2.enabled: false`，返回 503 是正常保护。
- “配置保存了但没生效”：实际是监听端口/TLS 需要重启。
- “机器人不回复”：实际是平台侧没有正确配置回调 URL 或验签参数。

提交问题时建议附：

```text
版本/提交：
启动方式：

复现步骤：

实际结果：
服务端日志：
浏览器控制台：
相关接口响应：
```

有了这些信息，定位速度通常会快很多。

## 摘要失败：`finish_reason="length"`

这表示模型在摘要完成前触及输出长度限制，不能将这段不完整文本替换为会话历史。它与请求超时或 MCP 工具不可用不同。

摘要请求的输出上限由 `multi_agent.eino_middleware.summarization_output_reserve_tokens` 控制，默认 40960 tokens。正文目标为该预算的一半（最多 2048 tokens），为格式和模型推理留出余量。发生明确的长度截断时，程序保留原输入并自动精简重试一次，正文目标降为预算的四分之一（最多 1024 tokens），输出上限保持不变。只有模型明确结束且正文非空的摘要才会写入后续上下文；再次截断则报错并保留原历史。

排查步骤：

1. 核对发生失败的会话实际选择的 AI 渠道和模型；它可能与当前默认渠道不同。
2. 查看摘要诊断中的输出预算及完成原因。`openai.max_total_tokens` 或 AI 渠道的 `max_total_tokens` 是上下文窗口预算，不是摘要输出上限。
3. 若持续失败，在确认供应商支持的输出上限及上下文余量后调整摘要输出预留；不要盲目增加数值。推理模型的隐藏推理也可能占用完成预算。
4. 修改配置后重启服务使配置生效，再继续原会话。认证失败、内容过滤、缺失结束标记和流中断不会被当作长度问题放行；网络错误仍使用原有重试策略。

自动精简不调用工具、不续写截断文本，也不把生成失败当作成功。它可增加一次模型请求及相应延迟和费用；不保证供应商在极小预算下必定返回完整摘要。

## HTTP 工具超时与不完整响应

`http-framework-test` 遇到网络失败时退出码仍为 1，同时输出 `Failure:` JSON。`error_code` 区分连接/TLS、读取、写入、连接池超时，以及 DNS、代理和 TLS 错误。`phase` 表示已知阶段：`response_headers_or_redirect` 包括等待响应头或处理跳转，`response_body` 表示最终响应头已到达。`response_status` 与 `received_body_bytes` 仅说明已收到的部分结果，不代表请求完整或成功。诊断不回显可能包含凭据、代理 URL 的原始异常文本。

`timeout` 必须为正有限秒数，默认 60；它约束每个网络等待阶段，不是整次调用总时限，执行器进程超时仍生效。非法值在连接前被拒绝。默认不额外探测 DNS/TCP/TLS；只有明确开启 `verbose_output=true` 才增加诊断连接，使用代理时跳过。探针每次 socket 操作最多等待 5 秒，DNS 仍由系统解析器处理。失败输出分别记录请求耗时与包含可选探针的整次操作耗时。

连接超时应检查路由、代理可达性；读取超时检查服务负载、反向代理和响应大小；写入超时检查网络及请求体大小。DNS、TLS 错误分别检查解析配置、证书链、主机名和系统时间。确认幂等性、授权范围与剩余调用预算后，才考虑有限次数重试；写入超时不代表服务端未处理请求。程序不会自动重试、切换工具或关闭证书校验。教育和企业 SRC 仍固定单次请求、每阶段 10 秒超时，并保留原有运行预算。

## Nmap 提示 `Bogus --host-timeout argument specified`

`720s` 本身是有效值。旧版 EV 参数拼接可能将 `scan_type` 插到 `additional_args` 的选项和值之间，形成 `--host-timeout -sT -sV 720s`。修复后扫描选项统一放在位置参数前，附加参数及引号内的值保持完整，无需转换超时单位。该修复需要重新构建并重启服务，同时更新 HTTP 工具 YAML。

修复不放宽 SRC 权限：仍只允许单个主机和最多 10 个明确端口，不允许端口范围，并使用强制低影响参数。参数回归测试不会扫描远程目标。

回归命令（Python 需安装 `httpx`、`PyYAML`）：

```sh
go test ./internal/security ./tests/internal/rolepolicy ./tests/internal/config
python -m unittest discover -s tests/tools -v
```

部署前备份现有程序和工具 YAML，保留本地工具定制，待无运行中任务后一起部署新程序与 YAML 并重启。回滚时两者一起恢复；无需数据库迁移或重置配置。

## 聊天首次打开慢、历史切换卡顿或空白

聊天页面改用 `GET /api/conversations/:id?message_limit=40&include_process_details=0`，先取最近 40 条。可选 `message_limit` 范围 1–100，`before_message_id` 游标按需读取同一会话的更早消息。响应保留原字段，新增 `messagePage: {hasMore, beforeMessageId}`；每页仍按时间正序排列。游标已删除、无效或属于其他会话时返回 400，界面提供重新加载；会话不存在返回 404。分页不能与全量过程详情同时使用。认证和资源权限不变，不传分页参数仍返回完整历史，导出及模型上下文不受影响。

页面小批量渲染，点击“加载更早的消息”补载，并保留阅读位置。切换会话会取消旧请求；网络请求及 JSON 解析超过 15 秒后显示重试按钮，不再一直空白。审批配置不阻塞消息显示，但发送消息仍等待审批配置就绪。Markdown 渲染异常时降级显示经过转义的纯文本。

网络或超时失败时，仅允许使用 60 秒内的缓存页，并明确标记为缓存；最多 12 页，单页正文不超过 100 万字符，总正文不超过 400 万字符。权限拒绝、会话删除及服务端错误不会使用缓存兜底。不会删除或压缩持久化消息。

图布局引擎改为打开图谱时加载，加载失败或超过 5 秒时使用现有基础布局。聊天启动不再等待该引擎或语言包；屏幕外消息及轮次导航减少重复布局与计算。导航栏仅对应已加载的消息，更早记录仍可补载或完整导出。

部署时一起更新程序、前端资源及模板；资源版本号会刷新浏览器缓存。启动时自动创建消息排序索引，不改变消息内容。部署前备份程序、相关文件和数据库，回滚时程序与前端一起恢复，新增索引可以保留。运行验证以 Linux 为目标。2,000 条模拟消息已验证首屏有界渲染、分页、快速切换和失败重试；实际延迟仍受消息大小、浏览器、网络及辅助服务影响。
